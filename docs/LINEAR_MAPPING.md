# Linear mapping (work in progress)

The route editor supports foreground GPS capture, manual points and GeoJSON import in EPSG:4326. It displays geodesic length and supports moving, deleting and inserting vertices. GPS capture is explicitly started and is stopped on exit; accuracy does not imply survey-grade positioning. Burial depth must be measured independently, never inferred from GPS elevation.

During route creation, users can record measured depth observations and junctions, enter type-specific attributes, and attach an exposed-trench photo. Existing routes allow additional depth observations from the asset detail page. Observations placed during creation must be re-placed if the route changes before saving; existing observations are not automatically relocated after an edit. The route and photo are separate writes, so a failed photo upload must be retried from the asset page. Offline route mutations and depth observations can be queued for replay by their original signed-in user. Do not use this work-in-progress for production field records.

Offline route creation, geometry edits and new depth observations are saved with their queue entries in a single local IndexedDB transaction. Pending asset edits are protected from replacement by server-list refreshes. In Supabase mode, supported route creates, edits and depth observations are replayed when online while the app is open and the same user is signed in. A database ledger makes retries idempotent and version mismatches require review. Failed items must be requeued manually; no conflict-resolution UI is implemented. Legacy queue items without capture-user identity, photos and non-route operations are not replayed. Demo-mode records remain local. Remote route create and geometry replacement use new security-invoker PostgreSQL functions that run the asset and child writes in one transaction. Geometry edits from the editor include a version check. An in-process PostgreSQL/PostGIS test covers rollback and selected RLS cases; a deployed Supabase/PostgREST integration test is still required. Do not use this work-in-progress for production records.
