# Linear mapping (work in progress)

The route editor supports foreground GPS capture, manual points and GeoJSON import in EPSG:4326. It displays geodesic length and supports moving, deleting and inserting vertices. GPS capture is explicitly started and is stopped on exit; accuracy does not imply survey-grade positioning. Burial depth must be measured independently, never inferred from GPS elevation.

During route creation, users can record measured depth observations and junctions, enter type-specific attributes, and attach an exposed-trench photo. Existing routes allow additional depth observations from the asset detail page. Observations placed during creation must be re-placed if the route changes before saving; existing observations are not automatically relocated after an edit. The route and photo are separate writes, so a failed photo upload must be retried from the asset page. Offline route mutations and depth observations can be queued for replay by their original signed-in user. Do not use this work-in-progress for production field records.

Offline route creation, geometry edits and new depth observations are saved with their queue entries in a single local IndexedDB transaction. Pending asset edits are protected from replacement by server-list refreshes. In Supabase mode, supported route creates, edits and depth observations are replayed when online while the app is open and the same user is signed in. A database ledger makes retries idempotent and version mismatches require review. Failed items must be requeued manually; no conflict-resolution UI is implemented. New point asset creations and photo and document uploads also replay for their capture user, in per-asset order. Photo and document storage and metadata are separate writes; retries compare existing bytes and metadata before confirming duplicates, and an upload may leave an orphaned storage object if metadata fails. Legacy queue items without capture-user identity and other unsupported operations are not replayed. Queued media is retained in IndexedDB but may not appear in the asset detail view until uploaded; check the Sync Queue for its status. Demo-mode records remain local. Remote route create and geometry replacement use new security-invoker PostgreSQL functions that run the asset and child writes in one transaction. Geometry edits from the editor include a version check. An in-process PostgreSQL/PostGIS test covers rollback and selected RLS cases; a deployed Supabase/PostgREST integration test is still required. Do not use this work-in-progress for production records.

Point creation and survey benchmark metadata use the atomic RPC in migration 20261118000600. Apply migrations in order and review existing migration history before deployment. Migration 20261118000900 replaces client-writable idempotency keys with protected replay receipts. It creates a non-login, non-BYPASSRLS replay role that inherits authenticated permissions; migration role-creation privileges, RLS, grants, and deployed Storage/PostgREST behavior require staging verification and security review before production. Old ledger entries remain untrusted: a queued mutation with a pre-migration ledger key is marked Requires Review rather than automatically acknowledged or reapplied. Reconcile those cases against server data and audit logs with an administrator; do not delete or blindly retry them. The UI does not yet provide a reconciliation workflow.

Other institution-level data and any additional policies still need a complete access review; campus selection is not a comprehensive confidentiality guarantee. Older media paths that do not match the enforced layout may become inaccessible and require administrator review. Live Supabase Storage and migration testing is required.
