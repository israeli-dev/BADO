# Linear mapping (work in progress)

The route editor supports foreground GPS capture, manual points and GeoJSON import in EPSG:4326. It displays geodesic length and supports moving, deleting and inserting vertices. GPS capture is explicitly started and is stopped on exit; accuracy does not imply survey-grade positioning. Burial depth must be measured independently, never inferred from GPS elevation.

During route creation, users can record measured depth observations and junctions, enter type-specific attributes, and attach an exposed-trench photo. Existing routes allow additional depth observations from the asset detail page. Observations placed during creation must be re-placed if the route changes before saving; existing observations are not automatically relocated after an edit. The route and photo are separate writes, so a failed photo upload must be retried from the asset page. Offline operations may be queued, but end-to-end replay of the new route payloads and transactional remote writes still require implementation and verification. Do not use this work-in-progress for production field records.

Offline route creation, geometry edits and new depth observations are saved with their queue entries in a single local IndexedDB transaction. Pending asset edits are protected from replacement by server-list refreshes. Queue processing is not implemented: reconnecting or requeueing does not upload records. Remote route writes are not yet transactional; do not use this work-in-progress for production records.
